### E02 — Decision tree (C4.5 approximation) and the paper benchmark for C4.5 (2026-10-28, utsav-s-r)

Hypothesis (holdout baseline): an unpruned entropy decision tree, the closest scikit-learn
model to C4.5, learns the timing patterns well above the E01 floor in every task, and on A1
comes close to the paper's C4.5 (per-class precision and recall 0.83-0.92 in the paper's
Figure 2).

Threshold (set before running, never moved afterwards):
- (a) validation macro F1 >= E01 validation macro F1 + 0.30 in all 16 configs;
- (b) A1 validation macro F1 >= 0.80 at every timeout (4 configs).
Supported only if both hold.

Hypothesis (paper benchmark, part of this experiment by decision of 2026-10-28): with the
paper's protocol (10-fold stratified CV on the whole file, predictions pooled over the folds)
and Weka's J48 defaults approximated, our tree reproduces the paper's A1 results. Duplicate
rows inflate 10-fold scores, because a flow's copy can sit in the training folds.

Threshold (paper benchmark, set before running):
- (c) on the rows as published, at least 12 of the 16 A1 chart values (2 classes x precision
  and recall x 4 timeouts, `reports/paper_baseline.csv`) are matched within +-0.05;
- (d) macro F1 on data v1 (deduplicated) is lower than on the published rows in at least 12 of
  the 16 files.
A2 and B are compared with the values the paper states in its text; no threshold, because
Figure 3 can't be assigned to C4.5 or KNN (see `reports/paper_baseline_NOTES.md`).

Note on what was seen before the thresholds were written: while testing the code, an unlogged
dry run on A1 15 s and B 15 s gave validation macro F1 0.890 and 0.759 for this tree. The
thresholds above cover all 16 configs and the benchmark, which had not been run.

Change vs E01: model `tree` = `DecisionTreeClassifier(criterion="entropy", random_state=42)`,
no depth limit, no pruning, no scaling (trees don't need it). Benchmark model `j48` =
`DecisionTreeClassifier(criterion="entropy", min_samples_leaf=2, random_state=42)`: Weka J48
defaults are `-C 0.25 -M 2` with pruning on (Weka Javadoc, `weka.classifiers.trees.J48`);
scikit-learn has no C4.5 pessimistic pruning, so only the 2-rows-per-leaf rule is copied.
Configs: `configs/experiments/E02_tree_<task>_<timeout>s.yaml` and
`E02_paper_j48_<rows>_<task>_<timeout>s.yaml` (`scripts/make_configs.py`). Rows for the
benchmark: `published` = every row of the ARFF file as published (duplicates kept, values
untouched, names from COLUMN_MAP; A1 120 s keeps its published `flowPktsPerSecond`) and
`v1` = all rows of data v1 (train + validation + test together, as the paper's protocol uses
the whole file; these scores are never used for model choice). Data version v1.

Result: 80 baseline runs, all FINISHED, from dev commit 1817c5a (committed and pushed;
tag v0.1-baseline). Numbers below come from `reports/baseline_tables.md` (generated by
`scripts/results_tables.py` from `reports/history.csv`). The 64 paper-benchmark runs (32 in this experiment) come from
dev commit 36c56a1 (the first attempt was refused by the pushed-code guard because generated
files were uncommitted; nothing was logged; the rerun came from the clean commit).

Holdout (validation macro F1, data v1):
- A1 0.890 / 0.864 / 0.857 / 0.857 (15 / 30 / 60 / 120 s); A2-VPN 0.825 / 0.828 / 0.775 / 0.780;
  A2-NonVPN 0.829 / 0.828 / 0.825 / 0.839; B 0.759 / 0.748 / 0.706 / 0.716. Best baseline in all
  16 configs. Gain over E01: 0.499 to 0.765.
- 5-fold CV agrees with validation: |CV mean - validation| <= 0.054, CV std 0.005-0.023.
- A1 ROC-AUC 0.858-0.890 (a single tree gives few distinct scores, so the curve is coarse).
- Macro vs weighted F1 gap 0.000 (A1) to 0.069 (B 60 s). Best class by F1: VOIP or VPN-VOIP
  (0.92-0.99) in every multi-class config; worst: VPN-CHAT, CHAT, STREAMING, MAIL or VPN-MAIL (0.42-0.71).
- Top confusion pair in B at every timeout: BROWSING vs VPN-BROWSING (29-45 validation flows each
  way): the tree knows the flow is browsing but not whether it went through the VPN. In A2 the
  confusions are among CHAT, FT and BROWSING.
- Complexity: unpruned trees of depth 16-35, 591-3,437 nodes. Cost: train 0.12 s (median),
  predict 0.30 ms per 1,000 flows, model file 134 KB median (593 KB max), peak fit memory 1.3 MB.
- B and A2-VPN score lower at 60 s and 120 s than at 15 s and 30 s. Class mix differs between
  timeouts (E00, point 10) and the 60 s files hold differently shaped VOIP and FT flows (E00,
  point 15), so this is not read as a timeout effect.

Paper benchmark (10-fold CV, pooled predictions; `notebooks/02_baselines.ipynb`):
- A1, published rows: all 16 chart values matched within +-0.05; largest difference 0.021
  (e.g. VPN precision 15 s: paper 0.890, ours 0.892; Non-VPN recall 120 s: 0.843 vs 0.853).
  On data v1 the values move by at most 0.053.
- A2 average precision at 15 s (paper 0.84 VPN, 0.89 non-VPN): ours 0.839 and 0.882 (macro mean)
  on published rows. B best-timeout average precision (paper 0.783): ours 0.770 macro, 0.808
  weighted, so the paper's "average" is probably the plain mean (not stated in the paper).
  B per-class precision at 15 s within 0.04 of the paper's text values; MAIL at 120 s is the
  largest miss (0.680 vs 0.790).
- Duplicates: on data v1 the 10-fold macro F1 is lower than on the published rows in only 6 of
  16 files (mean change +0.0013; range -0.018 to +0.014).

Surprise, and why (d) failed: the removed duplicates are mostly degenerate flows. 39-92% of
them have an identical feature twin with a different label (2-10% of all rows), and their
median flow has 0-2 packets (all flows: 8-43). Keeping every copy multiplies errors no timing
model can avoid, which offsets the leakage gain. Table "What the removed duplicates are".

Pilot (not part of the 80): the first end-to-end run (E_pilot-tree-A1-15s, commit 9365050) was
checked by hand in the MLflow UI against the plan's tracking table. It showed three gaps: no
feature-importance file, class counts only as a JSON file, and a clipped confusion-matrix title.
All three were fixed (commit b405b0d, merged as a6dbc83) and the pilot rerun gave identical scores
(validation macro F1 0.8901), which also showed the runs are deterministic.

Verdict: (a) supported (16 of 16 configs gain >= 0.30; smallest gain 0.499).
(b) supported (A1 0.890 / 0.864 / 0.857 / 0.857, all >= 0.80).
(c) supported (16 of 16 A1 values within +-0.05).
(d) not supported (6 of 16 files lower on v1; needed 12).

Decision: keep the decision tree as the reference baseline (best of E01-E03 in every config). Keep
the duplicate rule of data v1. The benchmark shows it does not inflate or deflate scores much
(about +-0.02), and it prevents train/test copies in our own protocol. The report states that
the hypothesis about inflation was wrong and why. Next: E04-E06 in Phase 3 must beat the tree's
validation macro F1.

MLflow runs: E02-tree-* (holdout), E02-paper-j48-* (benchmark, tag protocol=paper_10fold)
