### E02 — Decision tree (C4.5 approximation) and the paper benchmark for C4.5 (2026-10-28, utsav-s-r)

Hypothesis (holdout baseline): an unpruned entropy decision tree, the closest scikit-learn
model to C4.5, learns the timing patterns well above the E01 floor in every task, and on A1
comes close to the paper's C4.5 (per-class precision and recall 0.83-0.92 in the paper's
Figure 2).

Threshold (set before running, never moved afterwards):
- (a) validation macro F1 >= E01 validation macro F1 + 0.30 in all 16 configs;
- (b) A1 validation macro F1 >= 0.80 at every timeout (4 configs).
Supported only if both hold.

Hypothesis (paper benchmark, part of this experiment by decision of 2026-10-28): with the
paper's protocol (10-fold stratified CV on the whole file, predictions pooled over the folds)
and Weka's J48 defaults approximated, our tree reproduces the paper's A1 results. Duplicate
rows inflate 10-fold scores, because a flow's copy can sit in the training folds.

Threshold (paper benchmark, set before running):
- (c) on the rows as published, at least 12 of the 16 A1 chart values (2 classes x precision
  and recall x 4 timeouts, `reports/paper_baseline.csv`) are matched within +-0.05;
- (d) macro F1 on data v1 (deduplicated) is lower than on the published rows in at least 12 of
  the 16 files.
A2 and B are compared with the values the paper states in its text; no threshold, because
Figure 3 can't be assigned to C4.5 or KNN (see `reports/paper_baseline_NOTES.md`).

Note on what was seen before the thresholds were written: while testing the code, an unlogged
dry run on A1 15 s and B 15 s gave validation macro F1 0.890 and 0.759 for this tree. The
thresholds above cover all 16 configs and the benchmark, which had not been run.

Change vs E01: model `tree` = `DecisionTreeClassifier(criterion="entropy", random_state=42)`,
no depth limit, no pruning, no scaling (trees don't need it). Benchmark model `j48` =
`DecisionTreeClassifier(criterion="entropy", min_samples_leaf=2, random_state=42)`: Weka J48
defaults are `-C 0.25 -M 2` with pruning on (Weka Javadoc, `weka.classifiers.trees.J48`);
scikit-learn has no C4.5 pessimistic pruning, so only the 2-rows-per-leaf rule is copied.
Configs: `configs/experiments/E02_tree_<task>_<timeout>s.yaml` and
`E02_paper_j48_<rows>_<task>_<timeout>s.yaml` (`scripts/make_configs.py`). Rows for the
benchmark: `published` = every row of the ARFF file as published (duplicates kept, values
untouched, names from COLUMN_MAP; A1 120 s keeps its published `flowPktsPerSecond`) and
`v1` = all rows of data v1 (train + validation + test together, as the paper's protocol uses
the whole file; these scores are never used for model choice). Data version v1.
