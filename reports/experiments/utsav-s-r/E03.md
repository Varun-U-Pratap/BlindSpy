### E03 — KNN, Logistic Regression, SVM-RBF and the paper benchmark for KNN (2026-10-28, utsav-s-r)

Hypothesis (holdout baselines): KNN (k = 5) on standard-scaled features comes close to the
tree, since flows of one app sit near each other in timing space. Logistic Regression and an
RBF SVM, with plain standard scaling, do worse than the tree: the features are heavy-tailed
(microsecond times up to about 1.2e8 next to many -1 and 0 codes, E00), so after standard
scaling most flows are squeezed together, which hurts a linear boundary and a single RBF width.
All three still beat the floor. (Log transforms are tested in E04, not here.)

Threshold (set before running, never moved afterwards):
- (a) each of KNN, Logistic Regression and SVM-RBF beats E01 validation macro F1 by at least
  0.10 in all 16 configs;
- (b) KNN validation macro F1 is within 0.10 of the E02 tree in at least 12 of 16 configs;
- (c) Logistic Regression and SVM-RBF each score below the E02 tree in at least 12 of 16
  configs.
Each part gets its own verdict; the experiment is supported if all three hold.

Hypothesis (paper benchmark, part of this experiment by decision of 2026-10-28): with the
paper's protocol and Weka's IBk defaults, 1-NN reproduces the paper's A1 KNN results, and
duplicates inflate its 10-fold scores even more than the tree's, since a duplicate in the
training folds is always the nearest neighbour.

Threshold (paper benchmark, set before running):
- (d) on the published rows, at least 12 of the 16 A1 chart values for KNN are matched within
  +-0.05;
- (e) macro F1 on data v1 is lower than on the published rows in at least 12 of the 16 files.
A2 and B are compared with the values the paper states; no threshold (same reason as E02).

Note on what was seen before the thresholds were written: an unlogged dry run of the code on
A1 15 s and B 15 s gave validation macro F1 0.813 / 0.661 (KNN), 0.585 / 0.307 (Logistic
Regression) and 0.602 / 0.297 (SVM-RBF). The thresholds cover all 16 configs, of which those
two had been seen.

Change vs E01: three models, each a Pipeline with `StandardScaler` fitted on training rows
only, then `KNeighborsClassifier(n_neighbors=5)`, `LogisticRegression(max_iter=1000,
random_state=42)` (lbfgs; max_iter raised from 100 so the solver converges; all else
default) or `SVC(kernel="rbf", C=1.0, gamma="scale", random_state=42)`. SVM scores for
ROC/PR curves come from `decision_function` (no Platt scaling, which would add an internal
CV). Benchmark model `ibk` = `MinMaxScaler` + `KNeighborsClassifier(n_neighbors=1)`: Weka IBk
defaults are `-K 1` with `LinearNNSearch` and `EuclideanDistance`, which normalises each
attribute to its range unless `-D` is set (Weka Javadoc: `weka.classifiers.lazy.IBk`,
`weka.core.EuclideanDistance`, `weka.core.NormalizableDistance`). Configs:
`configs/experiments/E03_{knn,logreg,svm_rbf}_<task>_<timeout>s.yaml` and
`E03_paper_ibk_<rows>_<task>_<timeout>s.yaml`. Data version v1.

Storage check (plan: after E01-E03, every model saved): see the end of Result.

Result: 80 baseline runs, all FINISHED, from dev commit 1817c5a (committed and pushed; tag
v0.1-baseline). The 32 IBk benchmark runs come from dev commit 36c56a1 (see E02). Numbers below
come from `reports/baseline_tables.md` (generated by `scripts/results_tables.py` from
`reports/history.csv`).

| A1 | 0.813 / 0.825 / 0.813 / 0.807 | 0.585 / 0.598 / 0.541 / 0.576 | 0.602 / 0.610 / 0.545 / 0.621 | 0.890 / 0.864 / 0.857 / 0.857 |
| A2-VPN | 0.774 / 0.788 / 0.730 / 0.727 | 0.432 / 0.536 / 0.339 / 0.332 | 0.468 / 0.542 / 0.330 / 0.332 | 0.825 / 0.828 / 0.775 / 0.780 |
| A2-NonVPN | 0.773 / 0.783 / 0.750 / 0.769 | 0.449 / 0.486 / 0.447 / 0.482 | 0.487 / 0.468 / 0.441 / 0.471 | 0.829 / 0.828 / 0.825 / 0.839 |
| B | 0.660 / 0.647 / 0.617 / 0.637 | 0.307 / 0.320 / 0.271 / 0.270 | 0.296 / 0.311 / 0.278 / 0.274 | 0.759 / 0.748 / 0.706 / 0.716 |

- KNN is second everywhere, 0.039-0.101 below the tree. Its A1 ROC-AUC is 0.891-0.899, higher
  than the tree's 0.858-0.890, because 5 neighbours give smoother scores.
- Logistic Regression and SVM-RBF fail on the small classes: MAIL / VPN-MAIL F1 is 0.00 in most
  A2 and B configs, so macro F1 sits far below weighted F1 (gap up to 0.225, against
  0.000-0.087 for KNN). In A1 they lean heavily to one class (e.g. SVM 60 s: Non-VPN recall 0.95,
  VPN recall 0.22).
- The SVM keeps 55-88% of the training rows as support vectors (e.g. B 15 s: 11,076 of 12,651).
  So the RBF kernel on standard-scaled heavy-tailed features separates the classes poorly, as
  hypothesised. Logistic Regression converged in at most 244 iterations (limit 1,000; the default
  of 100 would have stopped early).
- Generalisation gap |CV - validation| <= 0.042 for all three; CV std <= 0.025.
- Cost (median over 16 configs): KNN trains in 0.01 s, but predicts 1,000 flows in 8.0 ms and
  stores the training set (1.2 MB median, 2.3 MB max). Logistic Regression: 0.08 s, 0.38 ms,
  3.8 KB. SVM: 0.63 s (2.9 s max), 210 ms (597 ms max), 1.1 MB (4.2 MB max). Peak fit memory
  is 3.0-3.6 MB (tracemalloc). For the SVM this is a lower bound, since libsvm's own memory isn't
  counted.

Paper benchmark, IBk (1-NN, min-max scaling):
- A1, published rows: 15 of 16 chart values within +-0.05. The largest miss is VPN recall at
  120 s (paper 0.860, ours 0.803). Example: VPN precision 15 s, paper 0.848, ours 0.863.
- B best-timeout average precision (paper 0.711): ours 0.710 (macro mean, published rows).
  Per-class B precision at 15 s is within 0.01 of the paper's text values. VPN-MAIL at 120 s is
  far off (paper 0.688; ours 0.820 on published rows, 0.521 on v1); the mail classes are small.
- Duplicates: v1 scores lower than the published rows in only 2 of 16 files (mean change +0.012,
  up to +0.040 for A2-NonVPN 120 s). The cause is the same as in E02: the removed duplicates are
  mostly 0-2 packet flows with twins of other labels. 1-NN copies the label of an identical twin,
  so extra copies add errors.

Verdict: (a) supported for all three models (each beats E01 by >= 0.10 in 16 of 16 configs;
smallest gains 0.455 KNN, 0.183 Logistic Regression, 0.187 SVM-RBF). (b) supported (KNN within
0.10 of the tree in 15 of 16; miss: B 30 s, 0.101). (c) supported (Logistic Regression and
SVM-RBF below the tree in 16 of 16 each). (d) supported (15 of 16 A1 values within +-0.05).
(e) not supported (2 of 16 files lower on v1; needed 12).

Decision: keep KNN as the strongest non-tree baseline; it gets the same tuning budget as the
best models in E07, as the plan says. Logistic Regression and SVM-RBF are kept as reported
baselines only. Next: E04 tests whether a log transform or RobustScaler fixes KNN's trouble with
heavy-tailed features. Storage: the user decides on joblib compression before Phase 3.

**Corrections and additions (recheck, 2026-10-28).**
- Model file sizes: KNN max 2.3 MB (was written 2.4), SVM median 1.1 MB and max 4.2 MB (was
  1.2 / 4.3; 4.3 MB is the SVM's largest whole run folder, not its model file). The run count
  is 147 (80 + 64 + 2 pilot + 1 smoke), not 146.
- Training times in these runs were measured with tracemalloc switched on. In a recheck (B 15 s,
  median of 5 fits) this slowed fitting by x1.00 for the SVM, x1.19 for Logistic Regression and
  x2.3 for KNN (0.012 s -> 0.027 s). The KNN and Logistic Regression training times above are
  overestimates by those factors; the ranking of models by cost doesn't change. From Phase 3 on,
  time and memory come from separate fits.
- `process_max_rss_mb` is the high-water mark of the whole batch process, not a per-run figure.
  It is not used anywhere and is no longer logged.
- The paper comparison is now also one table per task, for both row sources, with our per-class
  10-fold precision and recall and the paper's value where it gives one.
