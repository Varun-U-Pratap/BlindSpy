### Addendum to part 1 (31 Oct 2026, before the test set is opened): evaluation details

Part 1 said how the test set is used but left four details open. They are fixed here, before any
test score exists; part 1 above is not edited. Where this addendum and part 1 differ (the number

when this was written: the MLflow store has no run with a test metric (checked 31 Oct by query:

**1. Significance tests (confirmatory).** Exactly 26 paired tests, listed by run name below;
everything else is described only, with intervals but no test.
- Metric: macro F1 only. Accuracy, weighted F1 and the other metrics get intervals and are
  described, never tested, so no metric is picked after the fact.
- Statistic: d = macro F1 (headline) - macro F1 (other model) on the same test rows.
- Hypotheses: H0 d = 0, two-sided alternative d != 0.
- p-value from the paired bootstrap draws d*_1..d*_B (item 2):
  p = min(1, 2 x min((1 + #{d* <= 0}) / (B + 1), (1 + #{d* >= 0}) / (B + 1))).
- Holm step-down over all 26 p-values at family-wise alpha = 0.05; Holm-adjusted p-values are
  reported with the observed d and its 95% percentile interval.

**2. Bootstrap: 10,000 stratified paired resamples per task, seed 42** (replaces part 1's 1,000).
- Stratified: each resample draws, within each true class, as many test rows as that class has,
  with replacement, so every resample keeps the test set's class counts (the test split is
  itself stratified; smallest test class 36 rows, MAIL in A2-NonVPN and B). The intervals are
  therefore conditional on the observed class counts; this is stated with the results.
- Paired: one set of resample indices per task (numpy `default_rng(42)`), used for every model of
  that task, for the intervals and for the tests.
- Intervals: 95% percentile intervals (2.5th and 97.5th percentiles) for macro F1, accuracy and
  each difference d.
- Why 10,000 and not 1,000: with B resamples the smallest possible two-sided p is 2 / (B + 1).
  For B = 1,000 that is 0.0020, above Holm's first threshold 0.05 / 26 = 0.0019, so no test could
  ever reject. For B = 10,000 it is 0.0002.
- All intervals and tests are computed afterwards from each run's saved test predictions
  (item 4), not by refitting models.

**3. Calibration (E15) is settled on validation before the test set is opened.**
- Data: the 4 headline configs fitted on the training rows only (they reproduce the saved source
  runs exactly); ECE measured on the validation rows.
- ECE: confidence = the probability the model gives its predicted class; 15 equal-width bins on
  [0, 1]; ECE = sum over bins of (rows in bin / all rows) x |accuracy in bin - mean confidence in
  bin|; plus a reliability diagram.
- Calibrator: only isotonic, `CalibratedClassifierCV(method="isotonic", cv=5, ensemble=False)`,
  fitted on the training rows. `ensemble=False` fits the base model once on all the rows it is
  given and learns the isotonic mapping from 5-fold out-of-fold predictions, so the base model is
  the same single model as the uncalibrated one, and no validation label is used to fit the
  mapping. No other calibration method is tried, on validation or test.
- Adoption rule per task: calibration is adopted if the uncalibrated validation ECE is above 0.05
  AND the calibrated validation ECE is lower than the uncalibrated one. Decided per task and
  recorded in E15.md before the test set is opened.
- Calibration changes only the reported confidence, never the predicted class: the predicted
  class is always the uncalibrated model's argmax, and the confidence reported (predict.py, demo)
  is the calibrated probability of THAT class. Multiclass isotonic calibration can reorder class
  probabilities, so the argmax of the calibrated probabilities is never used as the prediction.
  Test macro F1, accuracy and all tests above are therefore unaffected by calibration.
- Final model: where adopted, the same calibrator is fitted on train + validation (base model =
  the train + validation retrain, the mapping from 5-fold out-of-fold predictions). The
  validation ECE is evidence for the decision only, not an independent measure of the final
  model's calibration; the test ECE (computed with the probabilities actually used: calibrated
  where adopted, else the original) is the one independent measure, reported once, with the
  uncalibrated test ECE beside it for reference.

**4. Rehearsal before the official test runs, and crash rules.**
- Rehearsal: the new run kind for the final runs is first run in a scratch clone with its own
  MLflow store (runner name other than utsav-s-r), with each model fitted on the training rows
  and scored on the validation rows in place of the test rows; a unit test shows that this mode
  never predicts on test rows. The rehearsal output must show: all 30 distinct models (the 4
  headline models among them), every logged field of the tracking table, each run's saved
  prediction file, the intervals for every model, all 26 tests with raw and Holm-adjusted p,
  data and split hashes equal to the manifest, and the git commit and lock-file hash.
- Each official run saves its test predictions (row id, true label, predicted label, class
  probabilities) as an MLflow artifact. The official runs go in one batch, from committed and
  pushed code, after the rehearsal passes.
- Crash before a run's test predictions are written: rerun that run with the identical committed
  config and code (deterministic, seed 42).
- Crash after predictions or metrics were written: do not refit; compute what is missing from
  the saved predictions.
- Any rerun after a test score was seen: allowed only as a technical rerun with identical code,
  data and config, documented here in part 2 with the reason; never a changed model or setting.
- Every attempt, failed or not, stays in MLflow and is listed in part 2.

### Correction to the addendum (31 Oct 2026, before the test set is opened; user OK)

Item 3 says `CalibratedClassifierCV(method="isotonic", cv=5, ensemble=False)`. In scikit-learn
`cv=5` means unshuffled folds; the training rows are in file order, so the out-of-fold
predictions the isotonic map is learned from were far worse than on random-split rows (A1
out-of-fold accuracy 0.6701 unshuffled vs 0.9321 shuffled; all 4 tasks in
`reports/fold_order_check.json`, training rows only). Found in the E15 pilot run on validation;
details in E15.md ("Correction before the runs"). The calibrator now uses
`cv=StratifiedKFold(5, shuffle=True, random_state=42)`, the project's folds. Nothing else in the
addendum changes (isotonic only, ensemble=False, training rows only, adoption rule, predicted
class always the uncalibrated one). Still no test-set score, prediction or metric exists.
