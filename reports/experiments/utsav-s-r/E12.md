### E12 — Final results on the test set (part 1 written 2026-10-28 in Phase 3, before the test set is opened; utsav-s-r)

Part 1 (this section) fixes, before any test score exists, which models Phase 4 scores, how,
and what we expect. Part 2 (Phase 4, tag v1.0-final) adds the results. Nothing in part 1 is
changed after test scores are seen.

What is scored (decided 28 Oct after E10, plan item "Decided 28 Oct, after E10"; generated by
`scripts/write_final_configs.py` from `reports/history.csv`; tables "Final choice per task",
"Comparison set" and "What the superseded 28 Oct tie rule would pick" in
`reports/phase3_tables.md`):
- Headline model per task (`configs/final/<task>.yaml`): the highest validation macro F1 of all
  model-selection runs, any experiment and timeout; only fallback a saved file over 50 MB (none
  needed):
  - A1: E17 LightGBM, tuned (E17-lgbm-A1-15s), validation macro F1 0.9308; next best E06
    XGBoost 0.9271;
  - A2-VPN: E08 LightGBM, tuned + class weights (E08-lgbm_class_weight-A2-VPN-15s), 0.8830; next
    best E08 LightGBM + oversampling 0.8830 (0.00001 lower);
  - A2-NonVPN: E08 LightGBM, tuned + random oversampling (E08-lgbm_oversample-A2-NonVPN-15s),
    0.9075; next best E17 SVM 0.9058;
  - B: E07 XGBoost, tuned (E07-xgb-B-15s), 0.8428; next best E08 XGBoost + class weights 0.8364.
  All four are 15 s models (no 30, 60 or 120 s run is above them).
- Comparison set (`configs/final/compare/<task>_<type>.yaml`, 28 configs): per task the best 15 s
  validation variant of each method type (decision tree, KNN, logistic regression, SVM-RBF,
  Random Forest, XGBoost, LightGBM). Every type had the same 50-trial tuning budget (E07, E17).
  Each headline model is also its type's comparison member (same source run), so it is trained
  and scored once and its score is used for both.
- Old-rule picks (`configs/final/old_rule/<task>.yaml`): what the superseded tie rule would pick,
  computed by code (`results.old_rule_choice`): A1 and A2-VPN the E04 signed-log KNN (k = 5;
  0.9048 and 0.8544), A2-NonVPN the E07 tuned KNN (0.8929, a comparison member), B the E17 tuned
  SVM (0.8242, a comparison member). Only the two not already in the comparison set get their own
  config.
So Phase 4 trains and scores 30 distinct models: 28 comparison members + 2 old-rule picks.

Check before writing this (Phase 3, nothing logged): every one of the 34 configs, built exactly
as written and fitted on the training rows, reproduces its source run's validation macro F1 to
all digits (34 of 34).

How (Phase 4, plan): each model is retrained on train + validation with its config's settings
and seed 42 and scored once on the seed-42 test set of its task at 15 s (A1 2,706 rows, A2-VPN
1,407, A2-NonVPN 1,305, B 2,712; smallest test class 36 rows; sizes from `data/manifest.json`).
Macro F1 and accuracy with 1,000-resample bootstrap 95% intervals. A difference between two models
of the same task is tested with a paired bootstrap on the same test rows, Holm-corrected for the
number of comparisons; otherwise it is only described. Only the 4 headline models are saved to
`models/final/` (committed); the others stay as MLflow artifacts. The test scores never change the
headline model (no choosing, swapping or re-tuning after test scores are seen).

Hypothesis: the validation scores were used for every choice, so they are slightly optimistic
(the top of 29-34 candidate runs per task, all timeouts), but the cross-validation spread is small (0.003-0.006
for the headline models), so the test scores should be close to the validation scores and the
order of the method types should mostly hold.

Threshold (set now, before the test set is opened, never moved afterwards):
- (a) every headline model's test macro F1 is within 0.03 of its validation macro F1;
- (b) the headline model scores above the old rule's pick on the test set in at least 3 of the 4
  tasks (point estimates; the paired bootstrap reports in how many the difference is clear);
- (c) per task, the order of the 7 method types by test macro F1 agrees with their order by
  validation macro F1 with Spearman correlation >= 0.8 in at least 3 of the 4 tasks.
Each part gets its own verdict.

Winner rule (decided 28 Oct; a 15 s validation macro F1 at least 0.03 above the task's current
best -> rerun at 30, 60 and 120 s): not applicable. E12 scores the fixed final and comparison
models once on the test set; no model is chosen, rerun or changed because of it.
