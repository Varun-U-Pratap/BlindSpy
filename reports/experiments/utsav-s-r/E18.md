### E18 — Post-hoc calibration of the A2-NonVPN and B headline models (2026-11-04, utsav-s-r)

Purpose (plan, Phase 6; agreed by the team 4 Nov): all four headline models should report a
calibrated confidence. Since E12, A1 and A2-VPN report the isotonic-calibrated probability of the
predicted class, while A2-NonVPN and B report the model's raw probability. E18 adds the same
isotonic calibrator to A2-NonVPN and B. The predicted class and every F1 score stay exactly as in
E12; only the confidence number changes.

Why (found 4 Nov in the demo): the A2-NonVPN model gives a confidence of 0.99 or higher on all 20
of its 20 demo sample rows. The cause is the E15 adoption rule (fixed 31 Oct, before the test set):
calibrate only if the raw validation ECE is above 0.05 AND isotonic lowers it. A2-NonVPN (raw
validation ECE 0.0444) and B (0.0350) fell below 0.05, so they kept the raw probabilities, although
E15 showed isotonic calibration lowers the validation ECE in all four tasks (A2-NonVPN 0.0444 ->
0.0152, B 0.0350 -> 0.0099). The 0.05 cut-off is a rule of thumb that no project data chose.
Both models are overconfident on the test rows: mean confidence 0.9942 (A2-NonVPN) and 0.9213 (B)
against a raw test ECE of 0.0339 and 0.0420 (E12, `reports/phase4_tables.md`).

Honesty rule: this decision is made AFTER the test set was opened (E12, 31 Oct) and after the test
ECE was seen. It is a post-hoc change and is reported as one here and in the report (sections 3.8,
4.22, 5.4, 5.10, 5.11, 6, 7 and 8). The E12 and E15 runs are never edited or deleted, the original
raw-confidence numbers (test ECE 0.0339 and 0.0420) stay in the report next to the new ones, and
the 0.05 rule stays recorded as what was decided on 31 Oct. The test rows of A2-NonVPN and B are
predicted once more, for the confidence only. No other calibration method is tried (no Platt
scaling, no temperature scaling) and nothing is chosen by looking at test numbers.

Method (the calibrated path E12 already used for A1 and A2-VPN; no new choices): for A2-NonVPN and
B, the headline config (`configs/final/<task>.yaml`, seed 42) is fitted on train + validation
inside `calibration.fit_calibrated`: `CalibratedClassifierCV(method="isotonic",
cv=StratifiedKFold(5, shuffle=True, random_state=42), ensemble=False)`. Label = the base model's
own prediction; confidence = the calibrated probability of that label
(`calibration.predict_with_confidence`); the run stops with an error if the calibrator's base model
predicts any row differently from the plain fit (`train.final_run`, as in E12). The logged
`protocol` parameter of an E18 run says the test rows are scored again after E12. The test rows are
predicted once more and saved as
`predictions/test_predictions.csv` with the same columns as the calibrated E12 runs (raw_row, true,
predicted, confidence, proba.<class>, calibrated_proba.<class>). Reported: test ECE (15 bins) with
the calibrated and the raw confidence, a reliability diagram on the test rows, mean confidence,
and the share of rows at confidence >= 0.99.

Evidence that the method works for these two pipelines: in E15 (fitted on train) both calibrators'
base models predicted the plain fit's class on 100% of validation rows
(`val_label_agreement_base_vs_plain` = 1.0 for E15-A2-NonVPN-15s, imblearn random oversampling +
LightGBM, and E15-B-15s, XGBoost). The calibrated argmax would differ on 0.84% and 0.77% of those
rows, which is why the label is always taken from the base model.

Hypothesis: because the base model inside the calibrator is the same plain fit as E12 (same rows,
same settings, seed 42), the predicted labels and the test macro F1 are unchanged, and because both
models are overconfident on the test rows, isotonic calibration lowers their test ECE, as it
lowered the validation ECE in E15.

Threshold (set before running, never moved afterwards):
- (a) the predicted labels equal the E12 saved test predictions on 100% of test rows, in both
  tasks (if not: stop, find the cause, and ask the team before going on);
- (b) the test macro F1 equals the E12 value exactly, compared unrounded (A2-NonVPN 0.9403,
  B 0.8480);
- (c) the calibrated test ECE is below the raw test ECE in both tasks (raw 0.0339 and 0.0420);
- (d) reported, no threshold: the share of demo-sample rows and of test rows at confidence >= 0.99,
  before and after. Isotonic calibration can still give 1.0 to flows in its top bin, so some rows
  may stay at 1.0; this is expected and written down before the run.
Each of (a)-(c) gets its own verdict.

Winner rule (decided 28 Oct): not applicable; E18 changes no model choice, setting or label.

Change vs E12: `calibrate: isotonic` for the A2-NonVPN and B headline configs; nothing else.
Configs `configs/experiments/E18_final_A2-NonVPN.yaml` and `E18_final_B.yaml` (copies of the E12
headline configs with `experiment_id: E18`, run name `E18-final-<task>`, `calibrate: isotonic`
and `protocol: final_test_calibration_post_hoc`; `scripts/make_configs.py`), data v1, 15 s.
The protocol tag keeps the two runs apart from the 30 E12 runs in every table; new run names keep
`results.load_history` (newest run per name) from swapping them for the E12 runs.

Rehearsal first, in a scratch clone with its own store (runner `rehearsal`,
`run_experiment.py --rehearsal`: fit on train, score validation, test rows unused). It calls the same
`calibration.fit_calibrated(pipe, X_train, y_train, 42)` as E15, so its validation ECE must equal
E15's isotonic values exactly (A2-NonVPN 0.0152, B 0.0099, compared unrounded with
`metrics.val_ece_isotonic`) and its labels must equal the E15 runs' validation labels.

MLflow runs: E18-final-A2-NonVPN, E18-final-B
