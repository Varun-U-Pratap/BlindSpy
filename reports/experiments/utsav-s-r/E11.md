### E11 — Session-aware split (does not run) (2026-10-28, utsav-s-r)

Planned test (plan, Phase 3): rerun the best models with a group split (GroupKFold) that keeps
all flows of one capture session on the same side, and report the drop in score. Flows of one
session share timing patterns, so a random split can put near-identical flows in train and test
and make scores look better than they would on a new session.

Why it does not run: E00 found no session information in the data. The ARFF files hold only the
23 timing features and the label: no flow IDs, IP addresses, ports, timestamps or capture-file
names (`data/manifest.json`: session_information false, reason "no IDs, IPs, ports, timestamps or
capture-file names"). Without them no session can be rebuilt, so a group split is not possible
from these files. Rebuilding sessions would need the original PCAP captures (a stretch goal in
the plan; only part of the non-VPN PCAPs is available).

What is done instead: exact duplicates were removed before the split, and none crosses train and
test (E00; data v1); E14 measures how much the scores move with the split seed; E16(b) keeps the
four timeout files apart, since the same flows appear in several of them (E00). The report lists
the missing session split as a limitation (section 7): the scores are for flows from the same
captures as the training flows, not for new sessions.

Hypothesis, threshold, winner rule: not applicable (no run).

MLflow runs: none.
