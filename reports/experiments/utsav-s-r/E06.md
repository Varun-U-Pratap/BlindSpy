### E06 — Gradient boosting: XGBoost and LightGBM with default settings (2026-10-28, utsav-s-r)

Hypothesis: gradient-boosted trees are usually the strongest model family on tables of
numbers. Each tree corrects the errors of the trees before it, which should help the classes
the forest still mixes up (VPN-CHAT, STREAMING, the mail classes). With default settings they
should at least match the 300-tree Random Forest (E05), and XGBoost and LightGBM, which use
similar algorithms, should score close to each other.

Threshold (set before running, never moved afterwards), validation macro F1 at 15 s, against
the current best after E05, the Random Forest (A1 0.9203, A2-VPN 0.8679, A2-NonVPN 0.8941,
B 0.8147; `reports/phase3_tables.md`):
- (a) the better of XGBoost and LightGBM beats the forest in at least 2 of the 4 tasks (any
  margin);
- (b) XGBoost and LightGBM are within 0.02 of each other in at least 3 of the 4 tasks.
Each part gets its own verdict.

Winner rule (decided 28 Oct, written here before running): a model whose 15 s validation macro
F1 beats that task's current best by at least 0.03 is a winner and is rerun at 30, 60 and
120 s with its 15 s settings. Why 0.03: it is above the largest Phase 2 CV standard deviation
(0.025), so a smaller gain could be noise from the split; a fixed number set before running
keeps the choice honest and repeatable. The current best is the highest 15 s validation macro F1
whatever the margin; the 0.03 only decides the reruns.

What E07 takes from this: per task, the best 2 of Random Forest (E05), XGBoost and LightGBM by
15 s validation macro F1 are tuned with Optuna (decided 28 Oct), plus the signed-log KNN.

Change vs the current best (one change: the model family): model `xgb` = `XGBLabelled`
(`src/blindspy/models.py`), XGBoost's `XGBClassifier` with every setting at its default
(100 rounds, learning rate 0.3, max depth 6, histogram trees) except `n_jobs=1` and
`random_state=42`; the wrapper only encodes class names to 0..k-1 for XGBoost and back. Model
`lgbm` = `LGBMClassifier` with defaults (100 rounds, learning rate 0.1, 31 leaves) except
`n_jobs=1`, `random_state=42` and `verbose=-1` (silences its log, no effect on the model). No
scaling and no log (trees). One thread per model, the 5 CV folds in parallel. Configs:
`configs/experiments/E06_{xgb,lgbm}_<task>_15s.yaml` (`scripts/make_configs.py`). Protocol as
before; test set untouched. Models saved with compression level 3. Data version v1.

New model types: the first run of each is checked by query (all tracking-table fields, plus
number of trees, mean and max depth and nodes read from the booster's own tree dump). The
memory measure that matters here is the child-process RSS: XGBoost and LightGBM allocate in C++,
which tracemalloc does not see.
