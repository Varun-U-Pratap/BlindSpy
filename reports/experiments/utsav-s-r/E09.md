### E09 — Feature-group ablation on the headline models (2026-10-28, utsav-s-r)

Purpose (plan: analysis only): which kinds of timing information the headline model per task
needs. It changes nothing about the final choice (E09 is not a model-selection experiment).

Hypothesis: the 23 features overlap a lot (E00: 19 of 253 feature pairs in A1 and B, 27 in
A2-VPN and 20 in A2-NonVPN have Spearman |rho| >= 0.9, mostly within the active / idle group), so
the model can make up for most missing groups with the others: dropping any one group should cost
little, while no single group alone carries as much as all 23. The only size-based feature is
flowBytesPerSecond; Jorgensen et al. found almost no loss when sizes were hidden by padding, so
dropping it (the timing-only set) should cost very little.

Threshold (set before running, never moved afterwards), validation macro F1 at 15 s against the
headline model with all 23 features (`configs/final/<task>.yaml`; A1 0.9308, A2-VPN 0.8830,
A2-NonVPN 0.9075, B 0.8428, table "Final choice per task" in `reports/phase3_tables.md`):
- (a) in all 4 tasks, every group alone scores below all 23 features;
- (b) in at least 3 of the 4 tasks, dropping any one group lowers macro F1 by at most 0.02;
- (c) in at least 3 of the 4 tasks, the timing-only set is within 0.01 of all 23 features.
Each part gets its own verdict.

Stop rule (decided 28 Oct): E09 is analysis only. If any feature set scores at least 0.03 above
all 23 features in a task, stop and ask the user before doing anything with it (it would mean a
feature set beats the chosen model by more than the winner margin). The winner rule (a 15 s
validation macro F1 at least 0.03 above the task's current best -> rerun at 30, 60 and 120 s;
0.03 because it is above the largest Phase 2 CV standard deviation, 0.025) therefore does not
start reruns here: such a result goes to the user first.

Change vs the headline model (one change: the feature set). Each run keeps the headline model's
type, every setting and its balancing (copied from `configs/final/<task>.yaml`, named in
`builds_on`); only the columns change. Feature groups, found by name in the data's columns
(`src/blindspy/features.py`), because A2 has total_fiat / total_biat where A1 and B have
std_fiat / std_biat (E00):
- fiat (forward inter-arrival times): min, max, mean, and std (A1, B) or total (A2) — 4;
- biat (backward inter-arrival times): the same 4;
- flowiat (inter-arrival times in both directions): min, max, mean, std — 4;
- active: min, mean, max, std — 4; idle: min, mean, max, std — 4;
- rates_duration: duration, flowPktsPerSecond, flowBytesPerSecond — 3.
Feature sets (13 runs per task, 52 in all): each group alone (`only_<group>`), all minus each group
(`no_<group>`), and `timing_only` (all but flowBytesPerSecond, 22 features). "all" is the
headline run itself, not rerun. Configs `configs/experiments/E09_<set>_<task>_15s.yaml`
(`scripts/make_configs.py`); the set is logged as param `feature_set`, the kept columns as
`features` and `n_features`.

Protocol as E04-E17: 5-fold stratified CV on train, fit on train, score on validation (the
features are dropped from all of them alike); test set untouched. Models saved with joblib
compression level 3. Data version v1.
