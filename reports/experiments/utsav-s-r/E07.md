### E07 — Hyperparameter tuning with Optuna, same budget for every model (2026-10-28, utsav-s-r)

Hypothesis: E05 and E06 ran with default settings. Tuning the main settings (number of trees,
depth, learning rate, row and column sampling, leaf size) to these data should improve each
model a little, since defaults are general-purpose. The tuned KNN (number of neighbours,
distance weighting, metric) gets the same budget so that no model wins only because it was
tuned more (Isnan et al. list untuned baselines as a weakness). Tuning should not change the
ranking: the tree ensembles stay ahead of KNN.

Threshold (set before running, never moved afterwards), validation macro F1 at 15 s; reference
values from `reports/phase3_tables.md`:
- (a) in at least 8 of the 12 searches, the tuned model scores above its own untuned version
  (E06 XGBoost, E05 Random Forest, E06 LightGBM, E04 signed-log KNN with k = 5);
- (b) the best E07 model per task beats the current best after E06, XGBoost with defaults
  (A1 0.9271, A2-VPN 0.8758, A2-NonVPN 0.9015, B 0.8303), by at least 0.01 in at least 2 of
  the 4 tasks;
- (c) the tuned KNN stays below the best tuned tree ensemble in all 4 tasks.
Each part gets its own verdict.

Winner rule (decided 28 Oct, written here before running): a model whose 15 s validation macro
F1 beats that task's current best by at least 0.03 is a winner and is rerun at 30, 60 and
120 s with its 15 s settings, tuned hyperparameters included (nothing is re-tuned per timeout:
that would be a different, 4 times costlier experiment). Why 0.03: it is above the largest
Phase 2 CV standard deviation (0.025), so a smaller gain could be noise from the split; a fixed
number set before running keeps the choice honest and repeatable. The current best is the
highest 15 s validation macro F1 whatever the margin; the 0.03 only decides the reruns.

Change vs the untuned runs (one change: the hyperparameters, chosen by search). Scope (decided
28 Oct; table "E07 scope" in `reports/phase3_tables.md`): per task the best 2 of Random Forest,
XGBoost and LightGBM by 15 s validation macro F1, plus KNN with the better of the E03/E04
preprocessing, which is the signed log + StandardScaler in every task:
- A1: XGBoost, Random Forest, KNN;
- A2-VPN, A2-NonVPN, B: XGBoost, LightGBM, KNN.
That is 12 searches. Each search: Optuna `TPESampler(seed=42)`, 50 trials run one after another
(parallel TPE trials are not reproducible), every trial scored by the mean macro F1 of 5-fold
stratified CV on the training rows (the folds of one trial run in parallel, each model on one
thread). Validation and test rows are never seen by the search. The best trial's settings are
then trained on all training rows and scored on validation exactly like any other run; that
model is saved. Trials keep settings and scores only (no model file); they are nested MLflow
runs tagged `trial=True`, protocol `optuna_trial`, and are kept out of the result tables.

Search ranges (fixed in the plan, written into `scripts/make_configs.py` and every
`configs/experiments/E07_<model>_<task>_15s.yaml` before running):
- Random Forest: n_estimators 100-1000; max_depth 5-40 or no limit; min_samples_leaf 1-10;
  max_features sqrt, log2 or a fraction 0.3-1.0.
- XGBoost: n_estimators 100-1000; learning_rate 0.01-0.3 (log scale); max_depth 3-12;
  subsample 0.5-1.0; colsample_bytree 0.5-1.0; min_child_weight 1-50.
- LightGBM: n_estimators 100-1000; learning_rate 0.01-0.3 (log scale); num_leaves 15-255;
  subsample 0.5-1.0; colsample_bytree 0.5-1.0; min_child_samples 1-50. LightGBM only uses
  `subsample` when `subsample_freq` > 0 (its default is 0), so its searches fix
  `subsample_freq=1` (sample rows anew for every tree); otherwise that range would do nothing.
- KNN (signed log + StandardScaler): n_neighbors 1-50; weights uniform or distance; metric
  euclidean or manhattan.
"No limit" and "fraction" are encoded as an extra categorical choice (`max_depth_limited`,
`max_features_kind`), so TPE samples them like any other setting (`src/blindspy/tuning.py`).

Logged per search (on the retrained run): trials, total fits (trials x 5 folds), best trial,
its CV macro F1 mean and standard deviation, search time, the search space and fixed settings,
`search/trials.csv` and `search/history.png` (score per trial and best so far). Because the
retrained run uses the same folds and seed, its CV mean must equal the best trial's exactly; this
is checked.

New model type: the first study's runs (trials and the retrained run) are checked by query.

Storage (plan): mlruns/ is measured again after the searches with the tuned model sizes.
