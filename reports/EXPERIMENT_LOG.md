### E03 — KNN, Logistic Regression, SVM-RBF and the paper benchmark for KNN (2026-10-28, utsav-s-r)

Hypothesis (holdout baselines): KNN (k = 5) on standard-scaled features comes close to the
tree, since flows of one app sit near each other in timing space. Logistic Regression and an
RBF SVM, with plain standard scaling, do worse than the tree: the features are heavy-tailed
(microsecond times up to about 1.2e8 next to many -1 and 0 codes, E00), so after standard
scaling most flows are squeezed together, which hurts a linear boundary and a single RBF width.
All three still beat the floor. (Log transforms are tested in E04, not here.)

Threshold (set before running, never moved afterwards):
- (a) each of KNN, Logistic Regression and SVM-RBF beats E01 validation macro F1 by at least
  0.10 in all 16 configs;
- (b) KNN validation macro F1 is within 0.10 of the E02 tree in at least 12 of 16 configs;
- (c) Logistic Regression and SVM-RBF each score below the E02 tree in at least 12 of 16
  configs.
Each part gets its own verdict; the experiment is supported if all three hold.

Hypothesis (paper benchmark, part of this experiment by decision of 2026-10-28): with the
paper's protocol and Weka's IBk defaults, 1-NN reproduces the paper's A1 KNN results, and
duplicates inflate its 10-fold scores even more than the tree's, since a duplicate in the
training folds is always the nearest neighbour.

Threshold (paper benchmark, set before running):
- (d) on the published rows, at least 12 of the 16 A1 chart values for KNN are matched within
  +-0.05;
- (e) macro F1 on data v1 is lower than on the published rows in at least 12 of the 16 files.
A2 and B are compared with the values the paper states; no threshold (same reason as E02).

Note on what was seen before the thresholds were written: an unlogged dry run of the code on
A1 15 s and B 15 s gave validation macro F1 0.813 / 0.661 (KNN), 0.585 / 0.307 (Logistic
Regression) and 0.602 / 0.297 (SVM-RBF). The thresholds cover all 16 configs, of which those
two had been seen.

Change vs E01: three models, each a Pipeline with `StandardScaler` fitted on training rows
only, then `KNeighborsClassifier(n_neighbors=5)`, `LogisticRegression(max_iter=1000,
random_state=42)` (lbfgs; max_iter raised from 100 so the solver converges; all else
default) or `SVC(kernel="rbf", C=1.0, gamma="scale", random_state=42)`. SVM scores for
ROC/PR curves come from `decision_function` (no Platt scaling, which would add an internal
CV). Benchmark model `ibk` = `MinMaxScaler` + `KNeighborsClassifier(n_neighbors=1)`: Weka IBk
defaults are `-K 1` with `LinearNNSearch` and `EuclideanDistance`, which normalises each
attribute to its range unless `-D` is set (Weka Javadoc: `weka.classifiers.lazy.IBk`,
`weka.core.EuclideanDistance`, `weka.core.NormalizableDistance`). Configs:
`configs/experiments/E03_{knn,logreg,svm_rbf}_<task>_<timeout>s.yaml` and
`E03_paper_ibk_<rows>_<task>_<timeout>s.yaml`. Data version v1.

### E01 — Majority-class baseline, all tasks and timeouts (2026-10-28, utsav-s-r)

Hypothesis: a model that always predicts the largest training class sets the floor every
model must beat. Its validation accuracy equals that class's share p of the validation set,
and its macro F1 equals 2p / ((1 + p) k) for k classes (F1 of the predicted class is
2p / (1 + p); every other class scores 0). The stratified split keeps p the same in train and
validation, so CV and validation should agree.

Threshold (set before running, never moved afterwards): supported if, in all 16 configs
(4 tasks x 4 timeouts), |validation accuracy - p| <= 0.001 and
|validation macro F1 - 2p / ((1 + p) k)| <= 0.001. Any miss means a bug in the pipeline or
the metrics, and the runs are not used until it is fixed.

Change: none (first baseline). Model `majority` = `DummyClassifier(strategy="most_frequent",
random_state=42)`. Configs: `configs/experiments/E01_majority_<task>_<timeout>s.yaml`
(generated by `scripts/make_configs.py`). Protocol: 5-fold stratified CV on train, fit on
train, score on validation (test not used). Data version v1.

Result: 80 baseline runs, all FINISHED, from dev commit 1817c5a (committed and pushed;
tag v0.1-baseline). Numbers below come from `reports/baseline_tables.md` (generated by
`scripts/results_tables.py` from `reports/history.csv`).

- All 16 configs match the arithmetic to 4 decimals (table "E01 check"): e.g. A1 15 s, largest
  class VPN, p = 0.5185, validation accuracy 0.5185, expected and measured macro F1 0.3414; B 15 s,
  largest class VOIP, p = 0.1560, macro F1 0.0193.
- The floor in validation macro F1: A1 0.337-0.358, A2-VPN 0.060-0.093, A2-NonVPN 0.067-0.096,
  B 0.019-0.030. Balanced accuracy is exactly 1/k (0.500, 0.143, 0.071) and A1 ROC-AUC 0.5.
- The largest class changes with the timeout (A1: VPN at 15/30 s, Non-VPN at 60/120 s;
  A2-NonVPN: VOIP at 15 s, BROWSING after; B: VOIP at 15 s, BROWSING after), as E00 found.
- CV on train equals validation (std 0.000): the stratified split keeps class shares equal.
- Cost: under 0.03 s to train, about 1.4 KB per model file.

Verdict: supported (16 of 16 configs within 0.001 on both checks).

Decision: keep as the floor. Every later model is compared with it. Next: E02, E03.

### E00 — Data findings and data v1 (2026-10-27, utsav-s-r)

Hypothesis (from the plan, written before the check): the ARFF `@ATTRIBUTE` names may not match
the data order. In A1 15 s row 1, `total_fiat` = 16 and `total_biat` = 4 in a 9.37 s flow, which
looks wrong; the paper's Table 2 and the authors' 2016 poster list fiat/biat as min, mean, max,
std, with no totals. Candidates: `total_*` are packet counts, `std_*`, or something else.

Threshold: no numeric threshold was written before the check. Decision rule used: a name list
is accepted for a file when every structural identity (min <= mean <= max per group, 0 <= std <=
max - min, gaps x (packets - 1) = duration) holds on 100% of applicable rows, allowing for the
source's rounding. A list is rejected when the identities fail on most rows.

Change: none to models. Built the parser (`src/blindspy/data.py`), the checks
(`src/blindspy/checks.py`), `scripts/prepare_data.py` and `src/blindspy/splits.py`, then data
version v1. Config: `configs/base.yaml` (`cleaning:`). Commit 0a36896. Data version v1.
Every number below is in `data/manifest.json` (keys named in brackets) or
`data/processed/v1/cleaning_log.csv`.

Result:

1. **Two header layouts.** 17 files use header "T" (`total_fiat`, `total_biat`, no std); the
   three 60 s files of A1 and B (incl. B-AllinOne) use header "S" (`std_fiat`, `std_biat`, no
   totals), the paper's list. [`files[].header`]
2. **Column-name check** [`column_name_check`]. Read under the S names, every A1 and B file
   passes fiat/biat min <= mean <= max and 0 <= std <= max - min on 100% of rows. Read under
   the T names, the same files pass min <= mean <= max on 0.00-0.02% and the packet-count
   identity on 0.00-0.05%. A2 files are the reverse: under the T names min <= mean <= max and
   "total/mean + 1, forward + backward = packet count (+-2%)" pass on 100%. Under the S names
   std <= max - min passes on 0%. The plan's packet-count test (mean_fiat x (total_fiat - 1)
   = duration +-10%) passes on 0-2% of rows in every file, so `total_*` are not packet counts.
   Verdict: A1 and B hold the paper's features, and 9 of their 12 headers shift the fiat/biat
   names by one pair. A2 holds `total_fiat`/`total_biat` (sum of the gaps) exactly as named.
3. **Final COLUMN_MAP** (`src/blindspy/data.py`; header name -> real content):
   - A1 and B files with header T: `total_fiat`->`min_fiat`, `total_biat`->`min_biat`,
     `min_fiat`->`max_fiat`, `min_biat`->`max_biat`, `max_fiat`->`mean_fiat`,
     `max_biat`->`mean_biat`, `mean_fiat`->`std_fiat`, `mean_biat`->`std_biat`. The other
